M365 Code Agent 0.16.4 - Installation and use
==========================================

English is the default release language. For Korean, see INSTALL.ko.txt and
README.ko.md. The extension UI remains Korean; model answers follow your request's
language unless you explicitly choose another response language.

This is an unofficial experimental extension, not a Microsoft product.
Use requires an eligible M365 Copilot account and organizational permission for
browser automation. Compatibility with every tenant/login flow is not guaranteed.

Requirements
------------
Windows, VS Code 1.106+ and Microsoft Edge.
No separate Python, Node.js, browser extension, Copilot Studio or AI API key is
needed to run this extension. Your project's test/build tools need their own
runtimes. Use a trusted local project; remote WSL/SSH/container workspaces are
outside this release's scope.

Install and use the existing M365 Agent chat
------------------------------------------
1. Open VS Code Extensions, choose ... > Install from VSIX..., and select
   m365-code-agent-0.16.4.vsix. Reload VS Code if prompted.
   Marketplace: https://marketplace.visualstudio.com/items?itemName=jhoon-dev.m365-code-agent
2. Open the local project you want to work on.
3. Click M365 Agent in the left Activity Bar or editor title toolbar. If an older layout remains, run
   "M365 Agent: 열기" from the command palette.
4. Click "연결" (Connect) below the input. The M365 Copilot browser editor shows
   the actual automated Edge page.
5. Complete login and MFA yourself, then open Copilot chat. For native certificate,
   passkey or other external authentication windows, switch to external browser
   mode using "외부 브라우저로 전환". Switching stops the task and restores the
   request to the input so it can be resent after login.
6. Enter a request in VS Code and press Enter or the send arrow. Shift+Enter adds
   a newline. Later input, submission and response collection are automatic.

Example: Fix src/average.js so an empty array returns null, and add a test.
Example: Remove src/legacy.js and update its imports.

Images, PDF, Word, Excel and videos (M365 Agent sidebar)
------------------------------------------------------
Choose "이미지·문서·동영상" to select local files, including files outside the
project, and ask for an analysis. The existing "+ 파일" workspace picker also
recognizes supported document/media extensions. Images and PDF/Word/Excel files
are uploaded through the signed-in Copilot website; ordinary workspace text
uses the existing text-context path. An upload failure stops the request.

Videos are decoded locally by bundled FFmpeg into three evenly sampled JPEG
frames with timestamps. Only those images are uploaded, not the original video.
This provides sampled visual analysis, without audio transcription or coverage
of every frame or events between samples. The model receives this limitation.

Select at most five files and keep the resulting native uploads within five
files (a video uses three). Defaults: 64MB per selected file, 100MB total;
settings: m365Agent.attachmentMaxFileSizeMB / attachmentMaxTotalSizeMB.
Native uploads have a separate channel from the 120,000-character prompt budget.
Smaller account/service limits and organizational upload permissions apply.
Files enter Microsoft's service and follow its retention/storage policies.
Upload readiness timeout: m365Agent.attachmentTimeoutSeconds (120 seconds).
For changed tenant UI, attachmentInputSelector / attachmentButtonSelector /
attachmentReadySelector / attachmentErrorSelector provide CSS overrides.
This feature is separate from the experimental VS Code model provider, which
still rejects image/binary API inputs. See README for formats and limitations.

The dedicated profile does not import your normal Edge profile/passwords. Login
expiry, MFA and CAPTCHA need direct user action. A first request can wait for
login readiness, normally up to ten minutes, and resume automatically. Failed
requests are restored without replacing a newer draft.

Default browser display is m365Agent.browserView=editor. It supports clicking,
scrolling, text and Korean IME; direct input is locked during automated actions.
Use external mode if necessary. Closing the browser editor does not stop the
task; ... > Copilot 브라우저 열기 reopens it.

Optional VS Code model provider - disabled by default
-----------------------------------------------------
1. Enable the USER setting m365Agent.experimental.modelProvider.enabled.
   Workspace settings cannot enable this feature.
2. Copy examples/m365-web.agent.md into the working project's
   .github/agents/m365-web.agent.md.
3. In Copilot Chat choose Agent "M365 Web" and model "M365 Web (Experimental)"
   from provider "M365 Code Agent (Experimental)".
4. Complete login/MFA in the separate dedicated external Edge window opened for
   this provider. Its profile is independent from the existing Webview profile.
5. Begin with a short question and the compact read/edit tool set.

The existing Webview remains available. In the provider path VS Code/the calling
extension executes tools and handles approval. Webview file hash/range checks
and its undo DO NOT apply. Host Chat/account/tool/organization requirements apply.

Important experimental limits:
- No token streaming; a complete validated JSON response is returned at once.
- Each VS Code Chat creates one web conversation at its first request. Follow-up
  questions and tool round trips reuse it; Chat switches restore the mapped URL.
  Successful browser sessions are reused. Existing web history is not deleted.
- Native Chat routing uses opaque references in assistant history (hidden in
  Markdown; visible in raw copies) and unique tool-call IDs because the stable
  provider API exposes no session ID. URL mappings survive extension reloads.
  Missing/stale identifiers or failed URL restoration stop the request without
  creating a replacement. Start a new Chat when switching from another model
  or continuing a provider Chat created before this update. See README for details.
- Web history is NOT disabled/deleted. Code, context and tool-result JSON may
  remain in each conversation under organizational retention/audit policies.
- Default provider budget is 120,000 characters, maximum 120,000. It is separate
  from the Webview's default 120,000 characters. Actual web input limits prevail.
- One measured first request required about 46K total characters. A smaller web
  input can reject even the compact Agent. Full default Agent/MCP tool sets can
  also fail the host's context preflight before reaching the provider.
- Old complete exchanges may be omitted, and exact repeated user text can
  reference its full source in the same request. System instructions, all user
  requests, recent tool exchange and tool schemas are retained. Unique content
  can still accumulate beyond the limit. Start a NEW CHAT first on context errors;
  if the first request fails, reduce tools/attachments or adjust a supported limit.
- Five user turns were verified in one VS Code 1.147.0 Copilot Chat: 48,000
  characters failed at turn three; 60,000 let the same Chat finish through turn
  five. Its final prompt was about 53.7K characters. This is not a fixed turn cap
  or a compatibility guarantee. See README.md for exact scope and limitations.

The M365 Web Model output channel records counts/phases/errors, not prompt,
response, file, argument, token or cookie contents. This does not disable web
conversation history. Disabling the provider stops active and pending requests.

Webview features and change review
---------------------------------
Use the same input for analysis, plans and edits. /ask, /plan and /review are
read-only. /agent allows ordinary Agent tools without forcing edits; /test is a
test shortcut. Attach up to five files or use the current file/selection.
Relevant paths and code are searched before the first request. Ranked search
and literal search support scoped paths and mark incomplete coverage.

Right-click selected code > M365 Agent for explanation, review or an edit request.
Use the error/warning lightbulb or Ctrl+. for a diagnostic-specific fix request.
Edit/quick-fix requests always enter review with automatic approval disabled.
Changed documents/diagnostics require a fresh request; save dirty files first.

Default "변경 승인" means change review: inspect file diffs and apply/reject.
Turning this off auto-applies validated ordinary edits, but deletion, execution
configuration and commands still require review. File tools reject stale hashes,
unread/overlapping edits, dirty files, excluded paths and links/junctions.

"승인 없이 진행" (Proceed without approval) is a SEPARATE option, off by default.
It also skips execution-config review and command approval for that task. File
validation and read-only restrictions remain. Shell commands run as your user,
can affect paths outside the project and are outside file-tool protections/undo.
Commands time out after 120 seconds and need the project's own installed tools.
They do not inherit a selected VS Code terminal's shell/virtual environment.

"요청 횟수 무제한" (Unlimited requests) independently removes the normal 100-round
extension ceiling. It does not remove approval, file checks, Stop or repetition
detection. Task options are frozen at start and stay visible when collapsed.

Undo covers up to 20 file-change batches in the current extension session, with
original bytes for deleted files, including binary/UTF-16/empty files. It refuses
to overwrite later edits or recreated paths and is lost on VS Code restart.
Terminal/MCP effects are not covered. Folder deletion checks the full tree,
refuses ignored/link/changed entries, removes only checked files/empty folders
and preserves new files. Limits: 1,000 folder entries, 32MB deleted-byte backup
per batch; normal file limits also apply. Do not treat shell deletion as protected.

Lookup MCP in the Webview uses explicitly selected MCP-tagged VS Code tools and
requires approval for every invocation, even with automatic approval enabled.
Use genuinely read-only server credentials: lookup-like names are only a filter,
not a sandbox or proof of read-only behavior. No MCP effects enter file undo.

History maps local conversations to web URLs and synchronizes the connected
rendered conversation while the sidebar is visible/idle. Local rename/delete
does not rename/delete web originals or project files. Imported JSON is not
executed. Answer font/wrapping/copy controls and a wide read-only answer editor
are available. Project check tests root reads/temporary writes without M365.

Troubleshooting and data handling
--------------------------------
Use ... > 연결 진단 (Connection diagnostics), even if the browser never opens.
Inspect failure stage/code in the M365 Code Agent output channel. Check browser
installation, profile access, ordinary M365 access and company proxy/certificate
policy. Configure composer/send/response selectors only if automatic detection
does not match your web UI. An existing company Code Assistant URL can be set
in m365Agent.copilotUrl; reload Webview connection settings afterward.

No separate token/cookie extraction, localhost HTTP relay, developer backend or
extension telemetry is used. Read source and tool results are sent to the signed-in
M365 website as prompts. Security/contract/data-label policies still apply. Name
filters cannot detect every secret; configure sensitive paths in .m365agentignore.
The extension does not bypass company policy, certificates or login controls.
