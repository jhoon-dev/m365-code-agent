M365 Code Agent 0.16.1 — 설치 및 사용
===================================

회사 Windows PC에 VS Code와 Microsoft Edge가 설치되어 있어야 합니다.
Python, 별도 Node.js, Edge 확장, Copilot Studio, API 키는 필요하지 않습니다.

1. VS Code 왼쪽 확장 화면을 열고 오른쪽 위 … → VSIX에서 설치…를 선택합니다.
2. m365-code-agent-0.16.1.vsix를 선택합니다. 필요하면 VS Code를 다시 로드합니다.
3. 수정할 로컬 프로젝트 폴더를 엽니다.
4. 왼쪽 활동 표시줄 또는 편집기 상단 도구 모음의 M365 Agent 아이콘을 클릭하고 입력창 아래 '연결'을 누릅니다.
5. VS Code의 M365 Copilot 브라우저 탭에서 회사 계정으로 로그인하고 MFA를 완료합니다.
6. Copilot 채팅 화면이 열린 상태에서 VS Code에 개발 요청을 입력하고 Enter 또는 ↑를 누릅니다.

이전 위치가 남아 있으면 명령 팔레트에서 M365 Agent: 열기를 실행하세요.
VS Code 1.106 이상이 필요하며 기본 사이드바의 사용자 배치 설정을 따릅니다.

이후 요청 입력·전송·응답 수집·파일 읽기·수정은 자동입니다.
프로젝트 분석은 수동 파일 첨부 없이 주요 소스를 먼저 읽어 시작합니다.
모드 선택 없이 수정할 내용을 요청하고, 변경 승인 대기 시 적용 버튼을 누르세요.
상단 더 보기(⋯) → 프로젝트 점검으로 M365 연결 없이 로컬 읽기와 임시 파일 쓰기·삭제를 검사할 수 있습니다.
매 요청마다 브라우저에서 보내기/복사/붙여넣기를 할 필요가 없습니다.
VS Code의 브라우저 화면에서 클릭·스크롤·키보드·한글 입력을 할 수 있습니다.
자동 입력·응답 수집 중에는 직접 입력을 잠급니다. 로그인 대기 중에는 직접 조작할 수 있습니다.
네이티브 인증 창이 필요하면 외부 브라우저로 전환하세요. 현재 작업은 중지되며 요청은 입력창에 복구됩니다.
기본 표시 위치는 m365Agent.browserView 설정(editor/external)에서 바꿀 수 있습니다.
로그인 만료, MFA, CAPTCHA가 나타나면 직접 처리해야 합니다.

예시 요청
src/average.js가 빈 배열을 받으면 null을 반환하도록 수정하고 테스트 파일도 만들어줘.
src/legacy.js를 삭제하고 참조하는 import도 정리해줘.
old-assets 폴더와 하위 파일·빈 폴더를 삭제해줘.

이미지·PDF·Word·Excel·동영상 분석(M365 Agent 사이드바)
--------------------------------------------------
'이미지·문서·동영상'에서 로컬 파일을 직접 고릅니다. 작업 영역 밖 파일도 선택할 수 있습니다.
기존 '＋ 파일'에서도 지원되는 작업 영역 문서·미디어를 선택할 수 있습니다.
이미지와 PDF·Word·Excel은 Copilot 웹에 실제 파일로 업로드하고 일반 작업 영역 텍스트는 기존 텍스트 문맥으로 보냅니다.
업로드 실패 시 파일 없이 요청을 계속하지 않습니다.
동영상은 포함된 FFmpeg로 로컬에서 일정 간격의 JPEG 3장을 추출하고 시각 정보와 함께 업로드합니다.
원본 영상은 업로드하지 않으며 음성 전사·모든 프레임·추출 화면 사이 사건은 분석 범위에 포함하지 않습니다.
이 한계를 모델에도 전달합니다.
최대 5개를 선택할 수 있으며 영상의 화면 추출 뒤 실제 업로드 수도 5개 이내여야 합니다(영상은 3개 사용).
기본 첨부 한도는 파일당 64MB·전체 100MB이며 m365Agent.attachmentMaxFileSizeMB / attachmentMaxTotalSizeMB로 조정합니다.
파일 바이트는 120,000자 프롬프트 예산과 별도인 업로드 경로로 보냅니다. 계정의 더 작은 한도와 조직 정책이 우선합니다.
첨부 파일과 화면은 Microsoft 서비스로 전송되어 해당 서비스의 저장·보존 정책을 따릅니다.
업로드 대기는 m365Agent.attachmentTimeoutSeconds(기본 120초)로 조정할 수 있습니다.
웹 구조가 다르면 attachmentInputSelector / attachmentButtonSelector / attachmentReadySelector / attachmentErrorSelector를 지정합니다.
실험용 VS Code 모델 제공자의 이미지·바이너리 API 입력 지원과는 별개이며 해당 입력은 계속 거부합니다.

같은 입력창에서 설명·분석·계획·수정을 요청합니다.
모델은 사용자 입력 언어를 기본으로 답하며, 응답 언어를 명시하면 그 지시를 우선합니다. 특정 단어 때문에 수정을 강제하지 않습니다.
작업이 끝나면 실제 적용한 파일 수를 별도로 표시합니다.
첫 요청을 보낸 후 로그인해도 요청을 보관하고 준비되면 자동 전송합니다(기본 최대 10분 대기).
실패한 요청은 VS Code 입력창으로 복원하며 새로 작성 중인 내용은 덮어쓰지 않습니다.
모델 불러오기로 현재 계정의 실제 웹 메뉴를 읽고 모델을 선택할 수 있습니다.
답변 아래 크게 보기로 읽기 전용 편집기 탭을 열고 넓게 읽을 수 있습니다.
읽기 설정에서 글자 크기와 코드 줄바꿈을 바꾸고, 코드별 줄바꿈·복사와 전체 답변 복사를 사용할 수 있습니다.
작업 기록은 접어서 표시하며 도구 실패는 자동으로 펼칩니다. 위쪽 답변을 읽을 때 스크롤을 유지합니다.
모델·현재 파일·변경 승인 설정은 입력창 아래 접힌 옵션에서 열 수 있습니다.
Shift+Enter 줄바꿈, ＋ 파일로 첨부, /ask /agent /plan /review /test 단축 요청을 지원합니다.
/ask는 읽기 전용, /agent는 일반 도구 사용을 명시합니다. 변경을 강제하지 않습니다.
검증 실패 후에는 대상 파일을 자동으로 읽어 교정합니다. 같은 실패나 읽기만 반복되면 원인과 적용 수를 표시하고 중지합니다.
기본 안전 한도는 100회(설정 최대 500회)이며 현재 요청과 안전 한도를 표시합니다. 새 결과가 있으면 계속하고 같은 읽기·실패·명령 결과가 반복되면 일찍 중지합니다. 기존에 직접 설정한 한도는 유지합니다.
모델 · 첨부 · 승인 → 요청 횟수 무제한을 켜면 해당 작업의 횟수 한도만 해제합니다(기본 꺼짐).
승인 없이 진행과 각각 독립적으로 선택하며 작업 중에는 바꿀 수 없습니다.
무제한에서도 반복 감지·중지·완료/오류 종료와 파일 검증을 유지합니다. 설정을 접어도 무제한 상태를 표시합니다.
상단 시계 모양 대화 기록 아이콘에서 제목 검색·열기·이름 변경·개별/전체 삭제를 할 수 있습니다.
이름 변경·삭제는 이 작업 영역의 VS Code 기록에만 적용되며 Copilot 웹 원본과 프로젝트 파일은 유지됩니다.
기록 전환·새 대화는 현재 자동화 탭을 재사용하며 작성 중인 웹 초안이 있으면 전환하지 않습니다.
연결된 웹 대화와 로컬 대화 주소를 함께 저장합니다. 기록을 선택하면 해당 웹 대화도 엽니다.
사이드바가 보이고 작업 중이 아닐 때 5초마다 현재 연결된 웹 대화의 질문·답변을 가져옵니다.
상단 더 보기(⋯) → 웹 대화 동기화로 즉시 동기화할 수 있습니다. 가져온 기록의 수정·명령 JSON은 실행하지 않습니다.
열지 않은 웹 대화 전체 다운로드, 로컬 과거 기록 전체 업로드와 삭제 동기화는 지원하지 않습니다.
기본값은 '변경 승인'입니다. 파일별 diff를 확인한 뒤 적용 또는 거절을 선택합니다.
체크만 끄면 일반 파일을 검증 후 자동 적용·저장합니다. 마지막 파일 수정은 되돌리기로 복원할 수 있습니다.
실행·빌드·CI 설정과 셸 스크립트는 변경 승인만 꺼도 계속 검토가 필요합니다.
승인 없이 진행을 별도로 켜면 파일·실행 설정·터미널 명령을 자동 승인합니다(기본 꺼짐).
작업을 시작할 때 정책이 고정되며 작업 중에는 바꿀 수 없습니다. 접힌 설정에도 자동 승인 상태를 표시합니다.
자동 승인에서도 파일 경로·비밀 파일·해시·읽기 범위·저장하지 않은 변경 보호와 읽기 전용 모드를 유지합니다.
명령은 사용자 권한으로 실행되며 프로젝트 밖 파일에도 영향을 줄 수 있고 명령으로 바뀐 파일은 확장 되돌리기에 포함되지 않습니다.
파일 도구의 경로·비밀 파일 차단은 셸 명령에 적용되지 않습니다. 모델에 셸 삭제를 하지 않도록 지시하지만 실행기에서 삭제 명령을 강제로 차단하지는 않습니다.
명령 승인 카드에서 이번 요청과 이전 요청의 변경 파일을 구분하고 diff를 확인할 수 있습니다.
저장하지 않은 사용자 변경이나 파일 해시 충돌이 있으면 덮어쓰지 않습니다.
테스트·빌드 명령은 기본적으로 표시된 명령과 작업 폴더를 확인하고 매번 승인한 뒤 실행합니다. 승인 없이 진행을 켜면 이 승인과 실행 설정 검토도 생략합니다.
명령은 PC의 셸에서 실행됩니다. 프로젝트에 필요한 실행 도구는 별도 설치되어 있어야 합니다.
되돌리기는 확장 실행 동안의 파일 수정만 대상으로 하며 터미널 변경은 복원하지 않습니다.

기존 Code Assistant 에이전트를 사용하려면
해당 에이전트의 웹 주소를 VS Code 설정 m365Agent.copilotUrl에 입력하세요.
설정을 바꿨다면 VS Code의 '개발자: 창 다시 로드'를 실행하세요.

연결 문제가 있다면
- 상단 더 보기(⋯) → 연결 진단에서 현재 페이지, 입력창과 최근 전송 단계를 확인하세요.
- 로그인 상태와 회사 계정의 Copilot 사용 가능 여부를 확인하세요.
- M365 화면 구조가 다르면 composerSelector/sendButtonSelector/responseSelector 설정을 조정해야 할 수 있습니다.
- 회사 정책에서 브라우저 자동화를 차단하면 이 방식은 작동하지 않습니다. 정책을 우회하지 않습니다.

특정 계정과 예제 프로젝트에서 실제 Copilot 응답 수집·파일 수정·추가 요청 후 테스트 실행을 확인했습니다.
0.14.0 모델 제공자는 특정 계정·VS Code 1.147.0의 간소화 Agent에서 5턴을 확인했습니다. 모든 조직·MCP·전체 도구 Agent의 호환성을 의미하지 않습니다. 기존 Webview의 변경된 프롬프트와 조직별 정책은 별도 검증이 필요합니다.
로컬 모의 Copilot 페이지를 통한 실제 Edge 입력·응답 수집과 VS Code의 파일 편집·저장을 검증했습니다.
M365 데스크톱 앱과 직접 통신하는 공식 API 연동이 아니라, 웹 화면을 자동 조작하는 방식입니다.

읽은 파일 내용은 로그인한 M365 Copilot에 프롬프트로 전달됩니다.
다른 AI 서비스, 별도 개발자 서버, 텔레메트리로 전송하지 않습니다.
전체 동작·제약·개발 방법은 README.ko.md(한국어) 또는 README.md(영어)를 참고하세요.

파일·폴더 삭제
프로젝트의 텍스트·바이너리·빈 파일 및 하위 폴더 삭제를 지원합니다.
삭제 전에 파일 해시를 확인하고 변경 카드에 D · 삭제로 표시합니다.
기본 설정에서는 삭제 승인이 필요합니다. 승인 없이 진행을 켠 요청은 삭제도 자동 적용합니다.
저장하지 않은 편집, 파일 해시 변경, 제외 경로·비밀 파일·심볼릭 링크가 있으면 삭제하지 않습니다.
되돌리기로 원래 바이트(바이너리/UTF-16/빈 파일 포함)를 복원하며, 같은 경로가 다시 생기면 덮어쓰지 않습니다.
삭제 백업은 현재 확장 실행 메모리에 보관하며 묶음당 최대 32MB, 파일별 크기는 파일 크기 설정을 따릅니다.
VS Code 재시작이나 터미널 명령으로 삭제한 파일은 확장 되돌리기 대상에 포함되지 않습니다.
일괄 변경이 일부 실패해도 이미 삭제된 파일의 백업을 유지하고 재시도를 중단합니다.

폴더 삭제: 전체 트리 확인·해시 검증 후 알려진 파일과 빈 폴더만 삭제합니다.
제외 파일·링크가 포함되거나 트리가 바뀌면 중단합니다. 폴더당 1,000개 항목, 백업 총 32MB 제한입니다.
새 파일은 함께 지우지 않으며, 현재 실행의 되돌리기로 원본 바이트와 빈 폴더를 복원합니다.


0.14.0 실험용 VS Code 모델 제공자(기본 꺼짐)
사용자 설정 m365Agent.experimental.modelProvider.enabled를 켜고 examples/m365-web.agent.md를 프로젝트 .github/agents/m365-web.agent.md로 복사하세요.
Copilot Chat에서 M365 Web Agent와 M365 Web (Experimental) 모델을 선택합니다. 별도 전용 외부 브라우저에서 직접 로그인합니다.
기본 한도는 120,000자이며 Webview의 별도 한도도 기본 120,000자입니다. 실측 첫 요청은 약 46K자, 다섯 번째 턴은 약 53.7K자였습니다.
48,000자에서는 세 번째 턴에 실패했고, 60,000자로 조정한 뒤 같은 대화 5턴까지 확인했습니다. 고정된 지원 턴 수를 의미하지 않습니다.
한도 오류에서는 먼저 새 Chat을 시작하세요. 첫 요청부터 실패하면 도구·첨부와 실제 웹 입력창 한도를 확인하세요.
같은 VS Code Chat의 모델·도구 왕복은 연결된 웹 대화 하나에 누적되며 코드·도구 결과 JSON에 조직의 보존·감사 정책이 적용될 수 있습니다. 웹 기록을 끄거나 삭제하지 않습니다.
실제 토큰 스트리밍은 없으며, 제공자 경로에는 Webview의 해시·범위 검증·되돌리기가 적용되지 않습니다. 도구 실행·승인은 VS Code 호스트가 담당합니다.
기존 Webview는 유지됩니다. 편집기 선택 코드·진단 빠른 수정, 조회용 MCP와 관련 코드 검색의 상세 제약은 README.ko.md를 참고하세요.

0.14.1에서 수정한 자체 채팅의 분석 보고서 JSON 표시도 유지합니다. JSON을 읽기용 제목·목록으로 표시합니다. 저장 원문과 명시적인 JSON 출력·코드 예제는 보존합니다. 복사·크게 보기도 화면과 같은 내용을 사용합니다. 업데이트 후 VS Code 창을 다시 로드하면 기존 저장 답변에도 수정된 표시를 적용합니다.

대화별 웹 연결 (0.15.0)
VS Code Chat별 첫 요청에서만 웹 대화를 만들고, 후속 질문·도구 왕복은 같은 웹
대화를 이어 씁니다. 다른 Chat으로 전환하면 저장된 웹 주소를 복원합니다.
안정 모델 제공자 API에 세션 ID가 없어 숨겨진 Markdown 참조·도구 호출 ID를
사용합니다. 식별자 누락·오래된 분기·복원 실패 시 새 웹 대화를 만들지 않고
중단합니다. 참조는 원문 복사 시 보일 수 있습니다. 변경 전 제공자 대화나
다른 모델에서 전환하는 경우 새 VS Code Chat에서 시작하세요. 기존 웹 기록은
삭제하지 않습니다. Webview와 Copilot Chat 목록·제목은 별도로 유지됩니다.
