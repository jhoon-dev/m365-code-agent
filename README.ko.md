# M365 Code Agent

[English](README.md) | [한국어](README.ko.md)

**Experimental preview · Unofficial · Windows + Microsoft Edge**

An independent VS Code coding agent that uses your signed-in Microsoft 365 Copilot web session through Playwright.
It can read, search, create and edit files in your local workspace without a browser extension, clipboard relay or separate AI API key.
This project is not affiliated with, endorsed by, or supported by Microsoft. You need an eligible Microsoft 365 Copilot account and permission to use browser automation in your organization.

이 확장은 Microsoft가 제공하거나 보증하는 제품이 아닌 실험적 버전입니다. 특정 계정과 예제 프로젝트에서 실제 M365 Copilot 연동을 확인했으며, 조직별 로그인·웹 UI·보안 정책의 호환성을 보장하지 않습니다. 확인 범위는 아래 `실계정 확인 범위`에 기록합니다.

VS Code의 프로젝트를 읽고 수정하며, 로그인된 M365 Copilot 웹과 자동으로 대화하는 로컬 확장입니다.
별도 Edge 확장, 클립보드 중계, Copilot Studio, 외부 AI API 키를 사용하지 않습니다.

0.14.0은 기존 Webview와 함께 선택형 모델 제공자, 편집기 작업·진단 빠른 수정, 조회용 MCP, 관련 코드 검색을 제공합니다. 기본 배포 문서는 영어이며 설치 안내의 한국어 버전은 `INSTALL.ko.txt`입니다. 변경 내역은 [CHANGELOG.md](CHANGELOG.md)를 참고하세요.

0.16.2은 M365 Agent 사이드바에서 이미지·PDF·Word·Excel 원본 첨부와 동영상 장면 분석을 지원합니다. 두 실행 방식의 기본 전송 한도는 120,000자이며, Chat별 웹 대화 재사용과 기존 보호 기능을 유지합니다.

0.14.1은 분석 답변 본문에 들어온 프로젝트 보고서 JSON이 자체 채팅에 그대로 표시되던 문제를 수정합니다. 기존 기록도 읽기용 제목·목록으로 표시하며 원문 저장 내용은 유지합니다. 명시적인 JSON 출력 요청과 JSON 코드 예제는 그대로 보존하고, 복사·크게 보기에는 화면과 같은 내용을 사용합니다. 이 표시 처리는 JSON 내용을 파일·도구 동작으로 실행하지 않습니다.

## 인증정보 처리와 변경 보호

- **토큰·쿠키를 별도로 추출하거나 중계하지 않습니다.** 사용자가 전용 브라우저에서 직접 로그인하고 MFA를 완료합니다. 로그인 상태는 해당 브라우저 프로필에 보관됩니다.
- **확장이 별도 localhost HTTP 서버를 열지 않습니다.** Playwright로 웹 화면을 조작하며 비공개 Copilot API에 직접 요청하지 않습니다.
- **기존 Webview의 파일 도구는 읽은 범위와 SHA-256 해시를 검증합니다.** 변경 검토와 파일 도구 변경의 되돌리기를 제공합니다. `승인 없이 진행`에서는 실행 설정 파일 검토와 명령 승인도 생략됩니다. 셸 명령이 만든 변경에는 이 파일 도구 보호·되돌리기가 적용되지 않습니다.

이 방식이 조직의 보안 승인이나 Microsoft의 지원을 의미하지는 않습니다. 작업에 필요한 코드·대화·도구 결과는 로그인한 M365 Copilot 웹으로 전송되며, 브라우저 자동화 사용 여부는 조직 정책에 따릅니다.

## 실험용 VS Code 모델 제공자

기존 Webview와 병행해서 사용할 수 있는 선택 기능입니다. 기본값은 꺼짐입니다. VS Code 모델 선택기에 `M365 Web (Experimental)`을 제공하며, 웹에서 현재 선택된 실제 모델을 사용합니다. 특정 모델 이름이나 모델의 실제 컨텍스트 크기를 추정해 등록하지 않습니다.

1. 사용자 설정에서 `m365Agent.experimental.modelProvider.enabled`를 켭니다. 작업 영역 설정으로는 활성화할 수 없습니다.
2. VS Code Chat의 모델 관리/선택에서 `M365 Code Agent (Experimental)` 제공자의 `M365 Web (Experimental)`을 선택합니다. 호스트의 Chat 기능과 조직 정책에 따라 표시·사용 가능 여부가 달라질 수 있습니다.
3. 첫 요청에 열리는 **별도의 전용 외부 브라우저**에서 로그인·MFA를 완료합니다. Webview의 로그인 프로필을 복사하거나 쿠키를 가져오지 않으므로 최초 로그인은 별도로 필요합니다. 로그인 대기는 기존 `m365Agent.loginTimeoutSeconds`를 따릅니다.
4. 먼저 짧은 일반 질문을 확인한 뒤, 적은 수의 도구만 활성화해 도구 호출·결과 왕복을 확인하세요. 설정을 끄면 진행 중인 웹 응답을 중지하고 대기 요청도 거절합니다.

처음에는 [간소화 Agent 템플릿](examples/m365-web.agent.md)을 작업할 프로젝트의 `.github/agents/m365-web.agent.md`로 복사한 뒤, Copilot Chat의 Agent 선택기에서 `M365 Web`, 모델 선택기에서 `M365 Web (Experimental)`을 선택하세요. 템플릿은 읽기·수정 도구만 사용하고 터미널·외부 서비스 작업을 요청하지 않습니다. 현재 계정과 호스트에서 실제로 제공되는 도구·권한이 적용되므로 템플릿 자체가 보안 격리를 제공하지는 않습니다.

기본 `Agent`에서 모든 확장·MCP 도구를 활성화하면, 제공자 호출 전에 Copilot의 System/도구 문맥 예산 검사에 걸릴 수 있습니다. 이 경우 브라우저 자동화의 문맥 축소까지 도달하지 않습니다. 고정 도구 정의나 System 지시를 임의로 제거하거나 모델 용량을 부풀려 우회하지 말고, 간소화 Agent 또는 필요한 도구만 선택한 새 대화로 확인하세요. `Local` 실행 경로와 `Copilot` 실행 경로는 서로 다르며 모델만 바꾼다고 실행 경로가 바뀌지는 않습니다.

| 실행 경로 | 도구 실행·승인 | 변경 검증·되돌리기 |
| --- | --- | --- |
| 기존 M365 Agent Webview | 기존 파일 도구·명령 승인·조회용 MCP 정책 | 기존 파일 도구의 해시·읽은 범위 검증과 되돌리기. 셸·원격 도구 효과는 제외 |
| 실험용 VS Code 모델 제공자 | 호스트가 제공한 도구 호출을 VS Code에 반환. 실행과 승인은 VS Code/호출 확장이 담당 | VS Code/호출 도구의 보호 적용. **Webview의 해시 검증·수정 범위 제한·되돌리기는 적용되지 않음** |

실험 범위와 제한:

- 텍스트, System/User/Assistant 역할, 도구 정의, 호출 ID, 도구 결과를 변환합니다. System 역할은 JSON의 역할 구분과 브리지 지시로 보존하며, 웹 서비스의 실제 system 채널에 접근하는 것은 아닙니다. UTF-8 텍스트·JSON·XML DataPart와 문서화된 PromptTsx 텍스트 트리도 변환합니다. 이미지·바이너리·불명확한 PromptTsx 노드는 텍스트로 가장하거나 누락해서 보내지 않고 오류로 알립니다. 제공자가 로컬 파일·명령·MCP를 직접 실행하지 않습니다.
- 별도 브라우저 프로필과 직렬 대기열을 사용합니다. 최대 8개 진행·대기 요청을 허용하며, 대기 중 취소는 웹에 전송하지 않습니다. VS Code Chat별 첫 요청에서 웹 대화 하나를 만들고 후속 질문·도구 왕복은 같은 대화를 이어 씁니다. 다른 Chat으로 전환하면 연결된 웹 주소를 복원합니다. **정상 완료한 브라우저는 다음 턴에 재사용**합니다. 실패·취소·설정 변경·확장 종료 시에는 닫아 늦은 응답이나 이전 설정이 다음 요청에 섞이지 않게 합니다. Webview 대화 목록과 동기화하지 않습니다. 웹에는 Chat별 대화가 남습니다.
- **웹 대화 기록을 끄거나 자동 삭제하지 않습니다.** 전체 문맥·파일 내용·도구 결과가 포함된 매 왕복의 JSON 프롬프트가 같은 웹 대화 기록에 누적될 수 있습니다. 조직의 보존·감사 정책이 적용될 수 있으며, 로컬 진단에 본문을 남기지 않는 것과는 별개입니다.
- 안정 VS Code 모델 제공자 API에는 Chat/세션 ID가 없습니다. 실험용 경로는 응답 기록의 무작위 복원 참조와 고유 도구 호출 ID로 대화를 식별하고, 작업 영역 저장소에 웹 주소 매핑을 보관합니다. 참조 정의는 Markdown 화면에서 숨겨지지만 원문 복사 시 보일 수 있으며 모델 입력에서는 제거합니다. 매핑에는 질문·답변 본문을 저장하지 않습니다. 직접 세션을 관리하는 호출자는 `modelOptions.m365ConversationId`를 전달할 수 있습니다. 후속 요청의 식별자가 없거나 이전 분기·재생성의 식별자이거나 웹 주소 복원에 실패하면 요청을 중단합니다. 다른 모델에서 처음 전환할 때는 새 VS Code Chat에서 시작하세요. 이 변경 전 제공자 대화는 자동 복원할 수 없습니다. 첫 응답 실패로 복원 참조를 받지 못한 경우, 명시적 대화 ID 없이 다시 요청하면 새 웹 대화가 열립니다. 명시적 ID가 있는 호출자는 해당 ID의 저장된 웹 주소로 이어갈 수 있습니다.
- Webview 대화는 기존의 별도 URL 매핑을 유지하며 Copilot Chat 목록과 합치지 않습니다. 웹 제목·로컬 이름 변경/삭제·웹의 원시 JSON 표시는 양방향으로 맞추지 않습니다. 이미 누적된 웹 기록은 유지합니다.
- 실제 토큰 스트리밍은 지원하지 않습니다. **완성된 JSON 응답 검증 후** 텍스트와 도구 호출을 VS Code에 전달합니다. 웹 응답 시간 제한은 기존 `m365Agent.responseTimeoutSeconds`를 따릅니다.
- 제공자 전용 입력 한도는 `m365Agent.experimental.modelProvider.maxPromptCharacters`입니다(기본 120,000자, 최대 120,000자). Webview의 별도 기본 120,000자 한도와 별개이며 브리지 지시문·이력·도구 정의가 모두 포함됩니다. 웹 입력창의 실제 한도가 더 작고 **미전송이 확인된 경우에만** 해당 한도로 한 번 재구성합니다. 전송 여부가 불확실한 요청은 재전송하지 않습니다. 도구 개수의 고정 제한은 없으며, 응답당 최대 8개 호출을 지원합니다.
- 한도를 넘으면 오래된 답변과 도구 호출·결과 교환을 완결된 단위로 생략합니다. **모든 System 지시·사용자 요청(중간에 추가한 제한 포함), 최근 도구 교환과 모든 도구 정의를 유지**하며 코드나 최신 도구 결과를 중간에서 자르지 않습니다. 생략 수를 모델에 전달하고 응답에도 `문맥 축소` 안내를 표시합니다. 필수 문맥만으로 한도를 초과하면 전송 전에 오류로 알립니다. System 지시나 도구 정의만 수만 자인 Agent 요청은 웹 입력창에 따라 여전히 사용할 수 없을 수 있습니다.
- 한도 초과 시 완전히 같은 긴 사용자 텍스트 파트는 같은 요청 안의 원문 위치를 참조하도록 표현해 중복 전송을 줄입니다. 첫·최근 사용자 메시지는 그대로 유지하며, 참조의 원문도 같은 요청 안에 보존합니다. 공개 LM 입력만으로는 사용자 문장과 첨부 문맥을 확실히 구별할 수 없어 임의의 XML 태그나 텍스트 구간을 첨부로 간주해 삭제하지 않습니다. 서로 다른 첨부·환경 정보나 사용자 요청 자체가 계속 늘어나면 여전히 한도를 넘을 수 있으므로 새 대화가 필요합니다.
- 토큰 수는 UTF-8 바이트 수를 기준으로 한 근사치(바이트 수 ÷ 3, 올림)입니다. 입력 토큰 예산도 같은 단위를 사용해 글자 한도에서 브리지 여유를 뺀 값의 1/3으로 신고하며, 원시 글자 수를 토큰 수로 신고하지 않습니다. ASCII 기준의 전송 예산이므로 다국어 입력에서는 보수적인 값이며 최종 전송은 실제 글자 한도로 다시 검사합니다. 출력 토큰 수는 실험용 안내 값입니다. 웹 모델의 실제 토크나이저·컨텍스트/출력 한도는 조회하거나 강제하지 않습니다.
- 도구 이름·호출 ID·인자 객체와 필수 호출 여부를 검사합니다. 도구 인자의 스키마 검증과 실행 권한 확인은 실행하는 호스트/도구가 담당합니다. 웹 자동화의 지연과 JSON 응답 준수 여부 때문에 Agent 호환성과 성능을 보장하지 않습니다.

`출력` 패널의 `M365 Web Model` 채널에서 요청·응답 단계, 메시지/도구 수, 글자 수, 오류 코드를 확인할 수 있습니다. 프롬프트·파일 내용·도구 인자·모델 답변·토큰·쿠키는 이 진단 채널에 기록하지 않습니다. 요청 로그가 전혀 없고 Chat에 문맥 예산 오류가 표시되면 호스트의 제공자 호출 전 검사에서 중단된 것입니다.

제공자 설정과 실제로 사용하는 URL·브라우저 채널·선택자·로그인/응답 시간 제한을 변경하면 진행 중 요청을 중단하고 브라우저를 새로 연결합니다. Webview 전용 설정(`browserView`, Webview의 `maxPromptCharacters` 등)은 모델 요청을 중단하지 않습니다.

아래 실측 환경의 첫 요청은 메시지 약 39K자에 도구 정의 약 5K자와 브리지 지시를 더해 **총 약 46K자**가 필요했습니다. 계정의 웹 입력창 한도가 이보다 작으면 간소화 Agent도 첫 요청부터 실패할 수 있습니다. 이는 보편적인 최소 사양이 아니며 Copilot 버전·선택 도구·첨부에 따라 달라집니다. 오류의 실제 필요 글자 수와 입력 한도를 확인하세요.

**2026-11-19 대화 매핑 실계정 확인(VS Code 1.147.0):** Local / Ask 경로에서 A 첫 응답 → A 후속 질문 → 별도 B → A 재선택 후 질문, 총 4회 성공을 확인했습니다. A의 후속 질문 두 번은 원래 A 웹 주소를 유지했고 B는 다른 주소를 사용했으며 ALPHA/BETA 시험 응답도 섞이지 않았습니다. 시험 중 사용자 한도를 80,000자로 임시 조정한 뒤 원복했습니다. 이 호스트 설정에서는 기존 간소화 Agent에도 도구 91개·약 171K자가 전달됐고 Ask도 도구 20개·약 64K자로 당시 기본 60K를 초과했습니다. 도구 선택·Agent 마이그레이션과 호스트 설정에 따라 달라집니다. 최초의 문장만 답하라는 요청에서는 전송 JSON이 생략돼 text 필드와 외부 형식을 구분하도록 안내를 보강했으며 이후 4회는 완료됐습니다. 재시작 복원·도구 왕복 매핑은 실제 Edge 모의 페이지 및 네이티브 호스트 자동 테스트로 별도 검증했으며 이번 실계정 확인에서는 도구를 실행하지 않았습니다.

대화 매핑 변경 전인 2026-11-18~19 실제 확인 범위(VS Code 1.147.0): Copilot 실행 경로에서 읽기·수정만 선택한 Agent와 실제 M365 웹 모델을 연결했습니다. 별도 계산기 프로젝트에서 `a - b`를 `a + b`로 변경한 첫 실행은 제공자 입력 한도 120,000자 설정에서 확인했습니다. 토큰 예산 계산 단위를 맞춘 뒤 **당시 기본값 48,000자 설정에서도** 파일 읽기와 곱셈 함수 추가가 완료됐고, 저장된 파일의 덧셈·곱셈 결과를 별도 Node 검증 4개로 확인했습니다. 실제 해당 설정 요청은 메시지 약 39~41K자·도구 정의 약 5K자, 모델 요청 3회였습니다.

곱셈 함수 테스트에서는 수정과 재조회를 같은 응답에서 요청해 재조회가 수정 전 내용을 반환했습니다. 의존하는 호출은 다음 응답으로 분리하도록 브리지 지시를 보완한 뒤, 같은 48,000자 설정에서 뺄셈 함수 추가로 재검증했습니다. `읽기 → 수정 → 수정 후 재조회 → 한국어 완료 응답`이 모델 요청 4회로 완료됐고, 세 함수의 실행 결과를 별도 Node 검증 6개로 확인했습니다. 이 지시는 호스트의 도구 실행 순서를 강제하는 보호 장치는 아닙니다.

추가로 같은 Copilot 대화에서 사용자 요청 5턴을 검증했습니다. 48,000자 설정에서는 세 번째 턴의 수정·재조회 뒤 완료 응답에 필요한 최소 문맥이 48,370자가 되어 실패했습니다. 60,000자로 조정한 뒤 같은 대화를 이어서 다섯 번째 턴까지 완료했습니다. `square`, `cube`, `negate` 추가와 재조회, 초기·중간 사용자 제한 요약을 확인했고, 최종 요청은 메시지 약 46.9K자·도구 정의 약 5K자·브리지 지시를 포함해 약 53.7K자였습니다. 이 실측을 근거로 당시 제공자 기본 한도를 60,000자로 조정했습니다. 저장된 파일은 별도 Node 연산 검증 12개와 원래 세 함수의 소스 보존 검사도 통과했습니다. 실제 대화에서는 오래된 교환 생략을 확인했으며, 반복 사용자 텍스트 참조 경로는 별도 자동 테스트로 검증했습니다. 이 결과가 더 긴 대화나 더 큰 첨부의 처리를 보장하지는 않습니다.

기본 Agent의 전체 도구 구성은 문맥 예산 오류가 재현됐으며, 모든 Agent·MCP 조합의 호환성을 의미하지 않습니다. System 메시지와 48개 도구 정의를 포함한 자동 테스트 및 확장 호스트의 등록·발견 테스트는 이 실사용 확인과 별도로 유지합니다.

한도 초과 오류에서는 먼저 **새 Chat**을 시작하세요. 첫 요청부터 실패하면 간소화 Agent나 웹 입력창에서 지원되는 한도를 확인하세요. 대화 길이를 고정된 턴 수로 환산할 수는 없습니다.

## 설치

1. [Marketplace](https://marketplace.visualstudio.com/items?itemName=jhoon-dev.m365-code-agent)에서 설치하거나, `…` → `VSIX에서 설치…`에서 `m365-code-agent-0.16.2.vsix`를 선택합니다.
2. 프로젝트 폴더를 열고 왼쪽 활동 표시줄의 M365 Agent 아이콘 또는 편집기 상단 도구 모음의 아이콘을 클릭합니다. 명령 팔레트에서 `M365 Agent: 열기`로도 열 수 있습니다.
3. 입력창 아래 `연결`을 누릅니다. VS Code 편집기 탭에 `M365 Copilot 브라우저`가 열립니다. PC에 설치된 Edge의 실제 자동화 페이지를 이 탭에서 보고 조작합니다.
4. 이 브라우저 탭에서 **회사 계정 로그인과 MFA를 직접** 완료하고 Copilot 대화 화면으로 이동합니다. 마우스·스크롤·입력·한글 IME를 지원합니다. 네이티브 OS 인증 창이 필요한 경우 `외부 브라우저로 전환`을 사용하세요.
5. VS Code에서 작업 요청을 입력하고 Enter 또는 `↑`를 누릅니다. Shift+Enter로 줄바꿈합니다. 이후 입력·전송·응답 수집은 자동입니다.

회사 PC에는 VS Code 1.106 이상과 Microsoft Edge가 필요합니다. Python 또는 별도 Node.js 설치는 필요하지 않습니다.
기존 Edge의 기본 프로필이나 비밀번호를 가져오지 않습니다. 확장 전용 Edge 프로필에 로그인 상태를 보관하며 표시 모드를 전환해도 같은 프로필을 사용합니다.
첫 로그인, 인증 만료, MFA와 CAPTCHA는 직접 처리해야 합니다.

왼쪽 활동 표시줄 아이콘은 실행 바로가기이며, 채팅은 오른쪽 보조 사이드바에 열립니다. 편집기 상단 도구 모음의 M365 Agent 아이콘은 편집기 탭이 열려 있을 때 표시됩니다. 이전 버전 위치가 남아 있으면 이 아이콘을 클릭하거나 명령 팔레트에서 `M365 Agent: 열기`를 실행하세요. 이 명령은 M365 Agent 보기와 컨테이너만 기본 위치로 복원합니다. 보조 사이드바를 왼쪽으로 배치한 사용자 설정에서는 해당 사이드바 위치를 따릅니다.

## VS Code 브라우저 표시

기본값인 `m365Agent.browserView=editor`는 실제 Edge 화면을 VS Code Webview에 표시하고 직접 입력을 같은 페이지로 전달합니다. 모델의 자동 입력·전송·응답 수집과 모델 메뉴 조작 중에는 직접 입력을 잠급니다. 로그인 준비를 기다리는 동안에는 직접 입력할 수 있습니다. 상단 드롭다운에서 로그인 팝업 등 같은 전용 브라우저의 탭을 선택할 수 있습니다.

`더 보기(⋯)` → `Copilot 브라우저 열기`로 화면을 다시 열 수 있습니다. 브라우저 편집기 탭을 닫아도 현재 자동화는 계속됩니다. 네이티브 비밀번호 관리자·인증서 선택·패스키 등 별도 OS/브라우저 창이 필요한 흐름은 보장하지 않으며, 패널의 `외부 브라우저로 전환`을 사용하세요. 전환은 진행 중인 작업을 중지합니다. 준비 중이던 요청은 입력창에 복구되므로 로그인 후 다시 보낼 수 있습니다. 영구적으로 외부 창을 사용하려면 설정을 `external`로 바꾸고 창을 다시 로드하세요.

이 화면은 iframe 또는 VS Code의 실험적 BrowserTab API가 아닙니다. 기존 Playwright 페이지의 화면을 메모리에서 전달합니다. 별도 로컬 HTTP 서버·쿠키/토큰 추출·화면 파일 저장·웹 보안 헤더 변경을 사용하지 않습니다. 패널이 숨겨지면 캡처를 멈추며, 주소 표시에는 인증 쿼리·조각을 포함하지 않습니다.

## 답변 읽기

- 답변은 14px 본문과 넓은 줄 간격으로 표시합니다. 상단 `읽기 설정`에서 12~18px 크기와 코드 줄바꿈 기본값을 바꿀 수 있습니다. 설정은 이 VS Code 대화 화면에 보관합니다.
- 코드마다 `줄바꿈`과 `복사`를 제공하며, 답변 아래 `답변 복사`는 원래 Markdown을 복사합니다. 실제 클립보드 처리 결과를 표시합니다.
- `크게 보기`는 같은 답변을 읽기 전용 편집기 탭에서 넓게 엽니다. 프로젝트 파일을 생성하거나 변경하지 않습니다. 탭 하나를 재사용하며 자체 글자 크기·줄바꿈·복사를 지원합니다.
- 도구 실행과 시스템 안내는 연속된 `작업 기록`으로 접어 모읍니다. 실패한 도구는 자동으로 펼쳐집니다. 변경 검토와 명령 승인 카드는 계속 별도로 표시합니다.
- 위쪽 답변을 읽는 중에는 새 이벤트나 같은 웹 대화 동기화가 스크롤을 맨 아래로 옮기지 않습니다. `최신 응답`을 눌러 마지막으로 이동할 수 있습니다.
- 입력창은 내용에 따라 늘어나며 모델·현재 파일·변경 승인 설정은 접어서 표시합니다. 접혀 있어도 변경 승인 여부를 표시합니다. 프로젝트 점검은 `더 보기(⋯)` 안에 있습니다.

## 사용

채팅 중심으로 작업하고, 파일 문맥을 첨부하고, 도구 실행과 변경을 검토하는 흐름입니다.
GitHub Copilot·Codex·Claude Code의 일반적인 작업 방식을 참고한 독립 구현이며, 동일한 성능·기능 전체를 제공하는 제품은 아닙니다.

모드 선택 없이 같은 입력창에서 분석·계획·수정을 요청합니다. 알 수 없는 표현을 읽기 전용으로 막지 않습니다. 명확한 설명·검토·계획 질문에는 읽기 전용 보호를 적용하고 `/ask`, `/plan`, `/review`는 항상 읽기 전용입니다. 문장 판별은 완전한 의미 이해를 보장하지 않으며, 특정 단어만으로 파일 변경을 강제하지 않습니다. 기본값에서는 파일 변경과 명령 실행 승인을 유지하며, 사용자가 `승인 없이 진행`을 켠 요청은 해당 승인 단계를 생략합니다.

- 처음 요청을 보낸 뒤 로그인 화면이 열려도 요청을 보관합니다. 로그인·MFA와 입력창 로딩이 끝나면 자동 전송합니다(기본 최대 10분 대기). 제출 전에 입력창이 초기화된 경우에만 다시 입력하며, 이미 누른 전송 버튼을 자동으로 다시 누르지 않습니다. 실패한 요청은 VS Code 입력창에 복구합니다. 그동안 새로 작성한 내용은 덮어쓰지 않습니다.
- `모델 불러오기`로 현재 계정의 실제 웹 메뉴를 읽고 드롭다운에서 모델을 변경합니다. 웹에서 제공되지 않는 모델을 추가하거나 라이선스 제한을 우회하지 않습니다. 메뉴가 없거나 구조가 다르면 웹의 현재 모델로 작업할 수 있습니다.
- 모델 답변과 수정 요약은 현재 사용자가 입력한 언어를 기본으로 하며, “영어로 답해줘”처럼 응답 언어를 명시하면 그 요청을 우선합니다. `/review`·`/test`도 원래 입력을 보존합니다. 확장 UI와 작업 기록 문구는 한국어입니다.
- 답변의 제목·목록·표·코드 블록을 Markdown으로 표시하고 코드 복사 버튼을 제공합니다. 답변의 HTML과 외부 이미지는 실행·로드하지 않습니다.

- `＋ 파일`로 최대 5개 작업 영역 파일을 명시적으로 첨부합니다. `이미지·문서·동영상`은 작업 영역 밖 파일도 직접 고를 수 있는 로컬 파일 선택창을 엽니다. 이미지·PDF·Word·Excel은 Copilot 웹에 실제 파일로 업로드하고, 일반 텍스트 작업 영역 파일은 기존 텍스트 문맥으로 전달합니다. `현재 파일`은 열린 편집기 또는 선택 영역을 포함합니다.
- `/ask`는 읽기 전용으로, `/agent`는 파일·명령 도구를 사용할 수 있는 일반 작업으로 명시합니다. 자동 판별을 바로잡을 때 요청 앞에 붙이면 됩니다. `/agent`도 파일 변경을 강제하지 않습니다. `/plan`, `/review`, `/test`는 계획·검토·테스트 단축 요청입니다.
- 대화 문맥을 이어서 요청할 수 있습니다. `＋`는 새 대화, 시계 모양의 `대화 기록` 아이콘은 기록 목록을 엽니다. 제목 검색, 이름 변경, 개별 삭제, 전체 삭제를 지원합니다. 이름 변경·삭제는 현재 작업 영역의 VS Code 저장 기록에만 적용되며 Copilot 웹 원본과 프로젝트 파일은 유지됩니다. 삭제에는 확인창이 표시됩니다. 최근 20개 대화를 현재 VS Code 작업 영역의 로컬 저장소에 보관합니다. 기록 전환과 새 웹 대화는 현재 자동화 탭을 재사용합니다. 사이드바에서 다른 대화로 전환하면 첨부 선택이 초기화됩니다. 작성 중인 웹 초안이나 진행 중인 웹 응답이 있으면 전환하지 않습니다. 모델에 전달하는 이전 대화는 크기에 맞춰 최근 일부로 제한됩니다.
- 연결된 웹 대화의 주소와 VS Code 대화를 매핑합니다. 사이드바가 보이고 작업 중이 아닐 때 5초마다 현재 연결된 웹 대화를 읽습니다. 상단 `더 보기(⋯)` → `웹 대화 동기화`로 바로 동기화할 수도 있습니다. 웹에서 추가한 질문·답변은 로컬 기록과 다음 요청의 문맥에 반영합니다. 동일 메시지는 중복 추가하지 않고 로컬 도구 기록도 유지합니다. `기록`에서 연결된 대화를 고르면 해당 웹 대화도 다시 엽니다. 기록 선택·새 대화·작업 시작 이후 도착한 오래된 동기화 결과는 적용하지 않습니다.
- VS Code의 새 요청은 연결된 웹 대화로 전송됩니다. 과거 로컬 기록 전체를 웹으로 재전송하거나, 열지 않은 웹 대화 전체를 내려받거나, 삭제를 양쪽에 전파하는 기능은 아닙니다. 현재 연결된 탭에 렌더링된 메시지만 가져오므로 웹의 가상 스크롤·화면 구조에 따라 오래된 메시지가 빠질 수 있습니다. 이력 가져오기로 JSON 파일 수정·명령 실행을 재실행하지 않습니다. 원시 도구 프롬프트는 질문으로, 응답 JSON은 사용자에게 보일 설명으로 정리합니다. 웹 화면 자체의 원시 JSON 표시를 바꾸지는 않습니다.
- 파일 읽기·검색·명령의 진행 상태는 채팅의 도구 카드에 표시됩니다. 명령의 실제 출력은 `M365 Code Agent` 출력 패널에 표시됩니다.
- 첫 요청 전에 프로젝트 파일을 탐색하고, 파일명과 코드 본문으로 관련 코드를 검색합니다. 검색어가 나온 구간·진입점·설정 중 기본 예산에서는 최대 4개(작은 예산에서는 더 적은 수)를 범위 읽기해 실제 본문을 전달합니다. `현재 파일`이나 수동 첨부가 없어도 동작합니다. 전체 프로젝트를 모두 분석했다고 간주하지 않으며, 모델이 추가로 목록·검색·읽기를 요청합니다.
- 상단의 `프로젝트 점검`은 M365 연결 없이 파일 읽기와 임시 파일 생성·읽기·삭제를 검사합니다. 프로젝트 루트의 `.m365-agent-check-<임의 ID>.tmp`만 잠시 만들며 기존 코드는 수정하지 않습니다. 이는 루트에 대한 쓰기 점검으로, 모든 소스 파일의 개별 권한을 보장하지는 않습니다.

예: `src/average.js가 빈 배열을 받으면 null을 반환하도록 수정하고 테스트 파일을 만들어줘.`

- VS Code 확장이 로컬 파일 도구를 실행합니다. Copilot 웹 자체에는 로컬 파일 접근 권한을 주지 않으며, 확장이 읽은 본문과 도구 결과를 웹 프롬프트로 전달합니다.
- 읽은 파일의 해시가 맞는 수정안만 적용합니다. 수정 중 파일이 바뀌었거나 저장하지 않은 사용자 편집이 있으면 적용을 거부합니다.
- 기본적으로 `변경 승인`이 켜져 있습니다. 파일명을 눌러 VS Code diff를 열고 `적용` 또는 `거절`을 선택합니다. 체크를 해제하면 일반 파일의 검증된 수정안을 자동 적용·저장합니다. 실행 설정과 명령은 계속 승인이 필요합니다.
- `package.json`, `*.config.{js,cjs,mjs,ts,cts,mts,jsx,tsx}`, `.mocharc.js`, `.eslintrc.js`, `jest.setup.ts`, `setup.jest.js`, `test/setup.js`, `.pre-commit-config.yaml` 등 실행 설정·초기화 파일과 `conftest.py`, `pytest.ini`, `tox.ini`, `noxfile.py`, `gradlew`, `mvnw`, `.cargo/`, 작업·CI·빌드 설정과 셸 스크립트는 `변경 승인`만 꺼도 계속 검토받습니다. 아래 `승인 없이 진행`을 별도로 켜면 이 검토도 자동 승인됩니다. 명령 승인 카드에도 이번 확장 실행에서 해당 작업 영역에 적용한 파일 변경과 diff를 표시하고, 이번 요청과 이전 요청에서 변경한 파일을 구분합니다. 이전 요청의 변경 내역을 지우지는 않습니다. 이 보호 장치가 프롬프트 인젝션을 완전히 막거나 셸을 격리해 주지는 않습니다.
- 생성·수정·삭제 변경은 VS Code diff와 Git diff로 검토할 수 있습니다. 삭제는 `D · 삭제`로 표시하며 명령 승인 카드에도 삭제 상태를 표시합니다.
- `중지` 이후의 응답은 파일에 적용하지 않습니다. 이미 적용·저장된 파일은 유지합니다.
- `되돌리기`는 마지막 파일 변경 묶음을 복원합니다. 새로 만든 파일은 제거하고, 삭제한 파일은 원본 바이트로 복원합니다. 이후 사용자 편집이 있으면 덮어쓰지 않습니다. 최대 20개 묶음을 이번 확장 실행 동안 보관하며 VS Code 재시작 후에는 사용할 수 없습니다. 터미널에서 발생한 변경은 포함하지 않습니다.
- Agent가 테스트·빌드 명령을 요청하면 기본적으로 **실행할 명령과 작업 폴더를 표시하고 매번 승인**받습니다. `승인 없이 진행`을 켠 요청은 명령 승인도 생략합니다. 명령은 해당 PC의 기본 셸에서 사용자 권한으로 실행되며, 별도 샌드박스는 아닙니다. 120초 제한, 중지, 출력 크기 제한이 적용됩니다. 프로젝트 실행 도구(Node.js, Python 등)는 해당 프로젝트에 맞게 설치되어 있어야 합니다.
- 파일 변경은 생성·전체 교체·부분 수정·삭제를 지원합니다. 큰 파일은 `read_file`의 `startLine`/`startColumn`/`lineCount`로 나누어 읽고, 읽은 범위의 고유한 `oldText`를 `newText`로 바꾸는 `edit` 작업으로 고칩니다. `nextLine`/`nextColumn`으로 긴 한 줄도 이어 읽을 수 있습니다. 파일 해시 충돌, 읽지 않은 범위, 중복 문구, 겹치는 수정은 거부합니다. 전체 교체에는 전체 읽기가 필요합니다.
- 모든 완료 응답 뒤에 실제 적용 파일 수를 별도로 표시합니다. 모델이 설명만 반환하면 변경 0개를 표시하며, `changes` 응답을 강제하는 재요청은 하지 않습니다. 모델의 설명을 파일 적용 증거로 취급하지 않습니다.
- 이름 변경 전용 도구, 인라인 자동 완성, 원격·백그라운드 에이전트는 제공하지 않습니다.

`.git`, `node_modules`, 가상환경, `.env*`, 개인 키·인증서, `.npmrc`/`.netrc`, 확장자 없는 SSH 키, `credentials`, `*.tfstate*`, `appsettings*.json` 등의 경로와 루트 `.gitignore` / `.m365agentignore`에 지정된 파일은 제외합니다. 이름 기반 차단은 모든 비밀을 식별하지 못하므로 프로젝트의 민감 경로는 `.m365agentignore`에 추가하세요.
심볼릭 링크·정션 및 프로젝트 밖 경로는 접근하지 않습니다. 단일 로컬 폴더를 대상으로 동작하며 다중 루트에서는 작업할 폴더를 선택합니다.
### 이미지·문서·동영상 분석

`이미지·문서·동영상`에서 파일을 선택한 뒤 “이 Excel과 PDF의 수치를 비교해줘”, “이 녹화 화면의 오류를 설명해줘”처럼 요청합니다. PNG·JPEG·GIF·BMP·WebP 이미지, PDF, Word(`.doc`, `.docx`), Excel(`.xls`, `.xlsx`)을 웹의 기본 파일 업로드 기능으로 보냅니다. 실제 계정이 해당 형식을 허용해야 하며 [Microsoft 지원 형식 안내](https://support.microsoft.com/en-us/microsoft-365-copilot/file-formats-supported-by-microsoft-365-copilot)와 조직 정책이 적용됩니다. 업로드 실패 시 파일 없이 요청을 진행하지 않습니다.

**2026-11-19 VS Code 실계정 확인(VS Code 1.147.0):** 설치한 0.16.0 VSIX의 실제 사이드바 파일 선택창과 전송 버튼으로 회사 Copilot 계정에서 검증했습니다. 합성 이미지·PDF와 Word·Excel의 파일 안에만 있는 고유 코드를 읽었고, PDF 합계 43·Word 예산 차액 200·Excel 합계 87을 확인했습니다. 합성 동영상의 0.967·2.9·4.833초 화면은 빨강/FIRST → 녹색/MIDDLE → 파랑/LAST로 분석하고 음성·미추출 구간의 한계를 표시했습니다. 업로드 확인과 사이드바 결과 표시까지 확인했으며 모든 테넌트·정책·코덱·파일 크기를 보장하는 시험은 아닙니다.

동영상(`.mp4`, `.mov`, `.webm`, `.mkv`, `.avi`)은 포함된 FFmpeg로 로컬에서 일정한 간격의 JPEG 3장을 추출하고 시각 정보를 함께 전달합니다. 원본 동영상은 업로드하지 않습니다. 분석 범위는 추출한 화면에 한정되며 음성 전사·모든 프레임 분석·화면 사이 사건 확인을 제공하지 않습니다. 모델에도 이 한계를 전달합니다.

선택은 최대 5개이며 동영상이 화면 여러 장으로 바뀐 뒤 실제 업로드 수도 최대 5개여야 합니다. 첨부 기본 한도는 파일당 64MB·전체 100MB이며 `attachmentMaxFileSizeMB`·`attachmentMaxTotalSizeMB`로 조정합니다. 웹 서비스의 더 작은 한도가 우선합니다. 원본 파일 바이트는 120,000자 프롬프트와 별도인 업로드 경로로 전달합니다. 기존 텍스트 첨부의 별도 문맥 한도는 유지합니다.

직접 선택한 파일만 업로드하며 자동 프로젝트 탐색이 문서·미디어를 업로드하지는 않습니다. 파일과 추출 화면은 로그인한 Microsoft 서비스로 전송되어 해당 서비스의 저장·보존 및 조직 정책을 따릅니다. 이 기능은 **M365 Agent 사이드바**에 적용되며 실험용 VS Code 모델 제공자는 이미지·바이너리 API 입력을 계속 거부합니다. 업로드 대기는 `m365Agent.attachmentTimeoutSeconds`(기본 120초)로 조정하며 웹 구조가 다르면 `attachmentInputSelector`·`attachmentButtonSelector`·`attachmentReadySelector`·`attachmentErrorSelector`를 지정할 수 있습니다. `attachmentScopeSelector`는 첨부 카드와 업로드 상태를 포함하는 작성 영역을 지정하며 대화 이력은 제외해야 합니다.

업로드 중단 후 미전송 첨부가 남으면 전용 Copilot 페이지에서 첨부를 정리한 뒤 페이지를 새로고침하고 다시 요청하세요.

텍스트 파일 크기는 기본 16MB, 설정에서 최대 128MB입니다. 한 번의 변경은 최대 30개 파일, 변경 요청 본문 총 512KB로 제한합니다. 부분 수정은 큰 파일 전체 크기가 아니라 교체할 oldText/newText를 기준으로 이 한도를 계산합니다. 웹에는 파일 전체를 올리지 않고 필요한 범위를 전달합니다. UTF-8 및 BOM이 있는 UTF-16을 읽으며, 다른 인코딩은 VS Code에서 열린 문서의 텍스트를 사용할 수 있습니다.

검증 실패 후 같은 질문을 되풀이하지 않도록 후속 요청에 고정된 작업 ID·완료한 도구·적용 파일·최근 오류를 전달합니다. 실패한 수정안은 대상 파일을 범위 읽기하고, 삭제 대상은 실제 경로 종류에 따라 file_info 또는 folder_info로 확인해 내용·hash 교정을 요청합니다. 같은 결과나 검증 실패만 계속되면 무의미한 재전송을 중지하고 실제 적용 수·원인을 표시합니다. 새 범위를 읽거나 파일이 실제로 바뀐 경우는 새 근거로 처리합니다. 동일한 파일 내용을 다시 적용하는 수정안은 진전으로 세지 않으며 적용하지 않습니다. 명령은 매번 실제 실행하되 같은 명령·결과만 반복되면 중지합니다. 소스 변경 뒤 같은 테스트를 다시 실행하는 경우는 새 진전으로 처리합니다. 이를 통해 모델이 항상 복구한다고 보장하지는 않으며, 실패한 수정안을 임의로 적용하지 않습니다.

## 선택 코드와 오류 빠른 수정

편집기에서 코드를 선택하고 우클릭 → **M365 Agent**를 열면 다음 작업을 실행할 수 있습니다. 같은 명령은 명령 팔레트에도 있습니다.

| 메뉴            | 동작                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------- |
| 선택 코드 설명  | 선택한 범위의 동작과 주의점을 읽기 전용으로 설명합니다.                                         |
| 선택 코드 리뷰  | 선택한 범위의 버그·회귀·테스트 누락을 읽기 전용으로 검토합니다.                                 |
| 선택 코드 수정… | 수정 지시를 입력받고 변경안을 채팅의 diff 검토로 전달합니다. 입력을 취소하면 요청하지 않습니다. |

오류·경고 위치에서 전구 메뉴 또는 `Ctrl+.`의 **M365 Agent로 수정안 요청: …**을 선택하면 해당 진단의 문구·출처·코드·위치와 주변 코드를 전달합니다. 전구 메뉴를 표시하는 것만으로는 Copilot 요청이나 편집을 실행하지 않습니다. 자동 수정의 우선 동작으로 등록하지 않으며, 선택한 한 진단에 대한 수정안을 요청합니다.

편집기 요청은 최초 탐색을 대상 파일로 제한하고 필요한 관련 파일은 모델이 도구로 추가 확인합니다. 설명·리뷰는 파일 수정과 명령 실행을 허용하지 않습니다. 수정·빠른 수정은 사이드바의 다음 요청 설정과 별도로 **변경 승인 켜짐·자동 승인 꺼짐·요청 횟수 제한 켜짐**으로 실행합니다. 변경안을 확인한 뒤 적용해야 저장되며 기존 되돌리기를 사용할 수 있습니다. 작성 중인 채팅 초안과 다음 요청의 설정은 유지합니다.

실행 순간의 파일·문서 버전·선택 범위를 고정하므로 연결 중 편집기 포커스가 바뀌어도 다른 파일로 요청을 옮기지 않습니다. 지시 입력 또는 로그인 대기 중 코드가 바뀌거나 진단이 사라지면 현재 코드에서 다시 요청해야 합니다. 수정할 파일의 저장하지 않은 변경은 먼저 저장해야 하며, 설명·리뷰에는 현재 버퍼의 선택 텍스트를 사용할 수 있습니다. 신뢰한 로컬 프로젝트 안의 허용된 파일에서만 실행하고 진행 중인 작업을 중복 실행하지 않습니다. 선택 범위가 10,000자를 넘으면 본문을 생략하고 범위 정보를 전달해 필요한 부분을 읽도록 합니다.

## 파일·폴더 삭제

예: `src/legacy.js 파일을 삭제하고 이 파일을 참조하는 import도 정리해줘.`

- 프로젝트 안의 텍스트·바이너리·빈 파일을 삭제할 수 있습니다. 폴더와 빈 하위 폴더 삭제도 지원합니다. `folder_info`로 트리 전체를 확인한 뒤 같은 `delete` 작업으로 삭제합니다. 기존 제외 경로·비밀 파일·심볼릭 링크 보호는 그대로 적용합니다.
- 먼저 `read_file` 또는 `file_info`로 확인한 해시를 검증합니다. `file_info`는 파일만 처리하며 바이너리에도 사용할 수 있습니다. 폴더를 넘기면 `folder_info` 사용 안내와 함께 거부하고 폴더 삭제 권한을 기록하지 않습니다. `folder_info`는 폴더 전체를 확인한 트리 해시를 반환합니다. 파일 도구는 파일 경로·크기·바이트 해시만 모델에 전달합니다. 바이너리만 있는 폴더도 본문 분석으로 간주하지 않고 파일 정보를 확인해 작업합니다.
- 삭제는 기본적으로 검토가 필요하며, `변경 승인`만 끈 일반 파일 자동 적용에서도 삭제는 검토합니다. 명시적으로 **승인 없이 진행**을 켠 요청은 삭제도 자동 적용합니다. 변경 카드에서 `D · 삭제` 표시와 diff를 확인할 수 있습니다.
- 편집 중 저장하지 않은 내용이 있거나 확인 후 파일이 바뀌면 삭제하지 않습니다. 삭제 원본은 현재 실행의 되돌리기 백업에 보관하며 바이너리·UTF-16·줄바꿈·빈 파일도 원래 바이트로 복원합니다. 삭제 후 같은 경로에 새 파일이나 폴더가 생겼으면 덮어쓰지 않습니다.
- 파일별 크기는 파일 크기 설정을 따릅니다(기본 16MB). 한 변경 묶음은 최대 30개 작업이며 삭제 원본 백업 총량은 32MB입니다. 폴더 하나는 루트 포함 하위 파일·폴더 합계 1,000개까지 지원합니다. 제외 파일·폴더나 링크가 하나라도 포함되면 폴더 전체 삭제를 거부합니다. 백업은 메모리에 보관하므로 VS Code 재시작 후에는 확장 되돌리기로 복원할 수 없습니다.
- 폴더 삭제는 확인한 파일과 빈 하위 폴더를 순서대로 삭제하며 무차별 재귀 삭제를 사용하지 않습니다. 검토 후 트리가 바뀌면 거부하고, 실제 삭제 직전에 추가된 파일 때문에 폴더가 비워지지 않으면 중단합니다. 부분 적용 후 되돌리기는 확인된 파일 생성·수정·삭제와 사라진 빈 폴더를 한 번에 복구합니다. 사용자가 새로 추가한 파일은 유지하며, 삭제와 내부 파일 수정을 같은 묶음에 중복 지정하지 않습니다.
- VS Code가 일괄 변경 일부를 완료하지 못하면 이미 삭제된 파일의 백업을 유지하고 작업을 중단합니다. `되돌리기`로 복원할 수 있습니다. 터미널 명령으로 삭제한 파일은 이 백업에 포함되지 않습니다.

이 절의 해시·경로·백업 보호는 `changes` 파일 작업에 적용됩니다. 모델에는 삭제를 `changes`로 제안하고 셸로 삭제하지 않도록 지시하지만, 셸 실행기에서 삭제 명령을 강제로 차단하는 것은 아닙니다. 승인한 셸 명령에는 파일 도구의 프로젝트 경로·비밀 파일 차단이 적용되지 않으며, 명령이나 실행한 스크립트가 프로젝트 밖 파일에 접근·수정·삭제할 수 있습니다.

## 요청 횟수 무제한

기본 안전 한도는 100회입니다. 입력창 아래 `모델 · 첨부 · 승인`을 펼쳐 **요청 횟수 무제한**을 켜면 그 요청에 횟수 한도를 적용하지 않습니다. 기본값은 꺼짐이며, VS Code 대화 화면 상태에 선택을 보관합니다. 작업 시작 때 선택을 고정하고 실행 중에는 바꿀 수 없습니다. 설정을 접어도 `무제한` 상태를 표시하며, 실행 중에는 현재 요청 횟수를 계속 표시합니다.

이 옵션은 **승인 없이 진행과 독립적**입니다. 무제한만 켜도 파일·명령 승인을 생략하지 않고, 자동 승인만 켜도 횟수 한도는 유지합니다. 두 옵션을 각각 켜거나 함께 사용할 수 있습니다. 반복 감지, 중지, 완료·오류 종료, 파일 검증과 읽기 전용 제한은 유지합니다. 확장 자체의 요청 횟수만 해제하며 M365의 서비스 동작이나 로그인 절차는 바꾸지 않습니다.

## 승인 없이 진행

입력창 아래 `모델 · 첨부 · 승인`을 펼쳐 **승인 없이 진행**을 켜면 해당 요청에서 일반 파일·실행 설정 변경과 터미널 명령을 자동 승인합니다. 기본값은 꺼짐입니다. 선택은 VS Code 대화 화면 상태에 보관하며, 접혀 있어도 승인 상태를 표시합니다. 작업을 시작할 때 선택한 정책을 고정하고 작업 중에는 바꿀 수 없습니다. 모델 답변이나 프로젝트 설정으로 이 옵션을 켜지 않습니다.

자동 승인에서도 파일 도구에는 작업 영역 신뢰, 경로·비밀 파일 차단, 읽은 내용과 해시, 수정 범위, 저장하지 않은 변경 보호를 그대로 적용합니다. **실행 설정 파일의 강제 검토와 명령 승인도 생략**되므로, 모델이 실행 스크립트를 바꾸고 이어서 실행할 수 있습니다. 셸 명령은 사용자 권한으로 실행되며 프로젝트 밖 파일에도 영향을 줄 수 있고, 명령이 만든 파일 변경은 확장의 되돌리기 대상이 아닙니다. 반복 감지·시간 제한·중지는 이미 발생한 명령의 영향을 복구하지 않습니다. 파일 diff·자동 승인 기록·파일 도구 변경 되돌리기는 계속 제공합니다. `/ask`, `/plan`, `/review`의 읽기 전용 제한은 유지합니다. 로그인·MFA·CAPTCHA는 직접 처리해야 합니다.

## 모델 도구와 명령 실행

`read_file`, `file_info`, `folder_info`, `list_files`, `search_text`, `search_code`는 확장이 실행하는 로컬 파일 도구입니다. Agent 모드에서는 `run_command(command)`도 안내합니다. Copilot 웹의 내장 도구 권한이 아니라, 모델이 `kind: "tools"`의 `calls`에 요청하면 VS Code 호스트가 검증·승인 정책에 따라 실행하고 실제 결과를 다음 요청에 전달하는 JSON 프로토콜입니다. 파일 생성·수정·삭제는 별도의 `kind: "changes"`로 제안합니다.

명령 실행이 필요하면 모델은 승인 대기 문장만 반환하지 않고 `run_command` 호출을 제출해야 합니다. 호스트가 승인 화면을 표시하며, 승인 전에는 명령을 실행하지 않습니다. Ask/Plan 모드에서는 명령 도구와 호출 예시를 안내하지 않고, 모델이 임의로 호출해도 호스트가 거부합니다. 프롬프트 개선만으로 모델이 항상 올바른 도구 요청을 생성한다고 보장하지는 않습니다.

Agent 요청에는 명령 실행기의 실제 OS·셸 경로·절대 작업 폴더를 전달합니다. Windows에서는 `ComSpec`(기본 `cmd.exe`), 그 외에서는 `/bin/sh`를 명시해 실행합니다. 명령은 백그라운드 프로세스에서 실행하므로 VS Code 터미널에서 선택한 PowerShell이나 활성화한 가상 환경·현재 디렉터리 상태를 공유하지 않습니다. PowerShell·Bash 등이 필요하면 설치된 인터프리터를 명령에 명시해야 합니다.

## 조회용 MCP 도구 연동

VS Code에 연결해 시작한 MCP 서버의 도구를 기존 Language Model Tools API로 호출합니다. 확장이 서버 설정·인증 정보를 별도로 가져오거나 새 MCP 클라이언트를 실행하지 않습니다. VS Code의 서버 신뢰·인증·추가 확인 절차를 그대로 사용합니다.

1. VS Code에서 신뢰할 수 있는 **조회 전용 MCP 서버**를 연결하고 시작합니다.
2. 채팅의 `더 보기(⋯)` → **조회용 MCP 도구 선택**, 또는 같은 이름의 명령 팔레트 명령을 실행합니다. 선택하지 않은 도구는 사용하지 않으며, 선택은 현재 VS Code 작업 영역의 로컬 저장소에 보관합니다. 프로젝트 설정 파일이나 모델 응답으로 선택 권한을 켜지 않습니다.
3. `/agent 선택한 MCP 도구로 관련 API 문서를 조회해줘.`처럼 요청합니다. 모델은 선택된 도구 목록과 입력 스키마를 확인한 뒤 필요한 호출을 요청합니다. MCP 실행은 Agent 요청에서만 허용하며 `/ask`, `/plan`, `/review`의 읽기 전용 보호는 유지합니다.
4. **MCP 도구 실행 승인** 카드에서 실제 도구 이름과 JSON 인자를 확인한 뒤 `이번 도구 실행`을 누릅니다. 로컬 `승인 없이 진행`이 켜져 있어도 MCP 호출은 매번 승인합니다. 거절하거나 중지하면 실행하지 않으며, 시작된 도구에는 VS Code 취소 토큰을 전달합니다.

현재는 `read`, `get`, `list`, `search`, `query`, `lookup` 등 조회형 이름을 가진 MCP 태그 도구만 후보로 표시하고, 파일 쓰기·수정·삭제·명령 실행 등을 나타내는 이름은 제외합니다. **이 이름 필터는 샌드박스나 읽기 전용 보장이 아닙니다.** 공개 API에는 도구의 실제 부작용을 검증할 정보가 없으므로 서버 자체를 조회 전용 권한으로 제한해 사용해야 합니다. 서버가 직접 만든 로컬·외부 변경은 확장의 diff·되돌리기 대상이 아닙니다. 파일 생성·수정·삭제는 모델이 기존 `changes` 프로토콜로 제안하며, 기존 범위·해시 검증, 승인, diff와 되돌리기를 그대로 사용합니다. MCP가 반환한 코드·해시·JSON은 파일 수정 권한이나 자동 적용 명령으로 취급하지 않습니다.

선택할 수 있는 도구는 최대 20개이며 이름·설명·입력 스키마가 바뀌면 다시 선택해야 합니다. 입력 스키마가 5,000자를 넘는 도구는 제외합니다. 도구 인자는 12,000자·중첩 20단계·항목 2,000개까지 처리하고, 목록·스키마·결과는 요청 문맥 예산을 따릅니다. 긴 도구 목록은 `nextOffset`으로 이어 조회합니다. 결과는 텍스트만 전달하며 이미지·바이너리·Prompt TSX는 실행하거나 불러오지 않고 생략 수를 표시합니다. 도구 설명과 결과는 신뢰할 수 없는 참고 데이터로 취급합니다. 선택한 도구의 메타데이터·인자·결과 일부는 작업을 수행하는 M365 Copilot 프롬프트에 포함됩니다.

호출 제한은 기본 120초이며, 시간 초과 시 원격 실행 결과가 확인되지 않은 것으로 처리해 작업을 종료합니다. 거절·실패한 동일 호출을 같은 요청에서 자동 재시도하지 않습니다. 취소 토큰은 원격 서버의 중지나 이미 발생한 효과의 복구를 보장하지 않으며, 취소 뒤 늦게 도착한 결과는 다음 파일 변경에 사용하지 않습니다.

## 관련 코드 검색

`search_code(query, paths)`는 코드 구간의 BM25 점수와 파일 경로 일치를 함께 사용해 관련 파일·줄·열·짧은 본문을 반환합니다. camelCase·PascalCase·snake_case 식별자를 분리하며, “토큰 갱신”, “인증”, “결제” 같은 일부 한국어 개발 용어를 영어 검색어로 확장합니다. 일반적인 의미 검색이나 임의의 한영 번역을 보장하지는 않습니다. 정확한 문자열은 기존 `search_text`로 검색합니다. 두 도구 모두 `paths`에 상대 파일·폴더를 지정해 범위를 좁힐 수 있으며 Ask/Plan에서도 사용할 수 있습니다.

검색 탐색은 기존 최초 1,000개·문자열 검색 500개에서 최대 20,000개 파일로 넓혔습니다. 루트 제외 규칙과 하위 `.gitignore`를 적용하고 링크·비밀 파일 및 `dist`, `build`, `coverage`, 잠금 파일 등 생성 결과를 제외합니다. 관련 코드 색인은 텍스트 파일 최대 10,000개, 파일당 256KB, 합계 32MB, 코드 구간 40,000개를 상한으로 합니다. 탐색은 디렉터리 10,000개·항목 100,000개까지 처리합니다. 큰 파일도 경로로 찾은 뒤 `read_file`로 필요한 범위를 읽을 수 있습니다. 검색 결과는 최대 20개, 문자열 검색은 최대 40개와 누적 파일 크기 64MB로 제한합니다.

생략·읽기 실패·한도 도달은 `truncated`, 검색/색인 파일 수, 생략 파일 수와 사유로 표시합니다. 일부만 검사했을 때 일치 결과가 없다는 이유로 프로젝트 전체에 코드가 없다고 간주하지 않습니다. 색인은 작업 동안 로컬 메모리에만 보관하고, 후속 검색마다 파일 목록·크기·수정 시각을 다시 확인해 변경·추가·삭제를 반영합니다. 검색은 편집기 버퍼를 읽거나 수정 권한을 부여하지 않으며, 실제 수정에는 기존 `read_file` 범위·해시 검증이 필요합니다. 로컬 색인 자체를 외부 서비스로 보내지 않으며 모델에는 입력 예산에 맞는 목록·검색 결과·읽은 범위를 전달합니다.

## 회사 Code Assistant 에이전트 사용

기존에 만든 M365 Code Assistant를 사용할 수 있습니다. 그 에이전트를 연 웹 주소를 VS Code 설정의
`m365Agent.copilotUrl`에 입력합니다. 필수는 아니며 일반 M365 Copilot 대화에서도 프로토콜 지침을 매 요청 전달합니다.
데스크톱 M365 앱에 직접 IPC/API로 연결하는 제품은 아닙니다. Edge에서 M365 웹을 자동 조작합니다.

## 연결 진단과 화면 변경

특정 계정의 실제 로그인·응답 수집은 확인했지만, M365의 화면 구조·실험적 UI·조직 정책에 따라 자동 감지를 조정해야 할 수 있습니다. 아래 확인 범위가 모든 회사 테넌트의 연동 검증을 뜻하지는 않습니다.
`더 보기(⋯)` → `연결 진단`은 현재 주소, 제목, 입력창 감지 결과와 최근 전송 단계를 VS Code 출력 패널에 표시합니다. 쿠키·토큰과 파일 내용은 연결 진단 로그에 기록하지 않습니다. 승인한 명령과 그 출력은 출력 패널에 표시됩니다.
응답이 화면에 보이는데 기다리는 경우에는 `응답 수집 진단`의 후보 수·현재 요청 ID 수·JSON 해석·생성 상태를 확인하세요. 수집은 코드 블록 외에 현재 요청 ID가 있는 작은 응답 영역, 열린 Shadow DOM과 자식 프레임도 탐색합니다. 언어명·복사 버튼 문구는 JSON 객체 밖에서 분리하며, 캡처한 답변 본문은 진단 로그에 저장하지 않습니다. 닫힌 Shadow DOM이나 화면에 전체 텍스트를 노출하지 않는 위젯은 수집하지 못할 수 있습니다.

설정에서 다음을 조정할 수 있습니다.

- `m365Agent.composerSelector`: 입력창의 CSS 선택자. 기본값은 자동 감지입니다.
- `m365Agent.sendButtonSelector`: 전송 버튼의 CSS 선택자. 기본값은 한국어·영어 버튼 자동 감지입니다. 활성화된 버튼을 클릭하고 입력창 초기화·생성 시작·새 응답으로 제출을 확인합니다. 제출을 확인하지 못하면 빠르게 오류를 표시하고 자동 재전송하지 않습니다.
- `m365Agent.responseSelector`: 응답 코드/메시지를 감싸는 CSS 선택자. 기본값은 코드 블록과 알려진 응답 컨테이너입니다.
- `m365Agent.responseTimeoutSeconds`: 응답 대기 제한(기본 240초).
- `m365Agent.loginTimeoutSeconds`: 로그인·입력창 준비 대기 제한(기본 600초). 대기 중 요청은 보관하고 `중지`로 취소할 수 있습니다.
- `m365Agent.modelButtonSelector`: 모델 선택 메뉴의 CSS 선택자(기본 자동 감지).
- `m365Agent.maxRounds`: 작업당 Copilot 요청의 보조 안전 한도(기본 100회, 최대 500회). 이전에 직접 설정한 값은 유지합니다. 작업 중에는 현재 요청 번호와 안전 한도를 표시합니다. 새 결과가 있으면 한도 안에서 계속하고, 새 결과 없는 반복은 한도 전에 중지합니다. `요청 횟수 무제한`을 켠 요청에는 이 한도를 적용하지 않으며 반복 감지와 중지는 그대로 유지합니다. 기본 120,000자 예산에서는 도구를 한 응답당 최대 4개 실행하며, 초과 호출은 실행하지 않았다고 명시해 다음 요청에서 다시 요청하게 합니다. 입력 예산에 따라 한 번에 1~4개를 허용합니다. 기본 입력 한도는 120,000자이며 웹 입력창의 실제 한도가 우선합니다.
- `m365Agent.maxFileSizeMB`: 로컬 파일 읽기·정보 확인 크기 상한(기본 16MB, 최대 128MB). 삭제 백업은 묶음당 총 32MB 이내입니다.
- `m365Agent.maxPromptCharacters`: 요청 길이 상한(기본 120,000자, 최대 120,000자). 입력창의 실제 한도가 더 작다고 전송 전에 확인되면 오래된 대화·파일 목록·첨부 문맥을 줄여 재구성합니다. 본문 범위를 더 줄일 때는 complete=false와 이어 읽기 위치를 명시합니다. 범위를 전달할 수 없으면 도구 오류로 모델에 알립니다. 사용자 요청과 코드 내용을 중간에서 잘라 보내지 않습니다.
- `m365Agent.browserView`: 기본 `editor`(VS Code 브라우저 탭). `external`은 별도 브라우저 창입니다.
- `m365Agent.browserChannel`: Edge(msedge) 또는 Chrome(chrome).
- `m365Agent.commandOutputEncoding`: 기본 `utf8`. CP949 전용 도구는 `cp949`로 설정합니다. Windows 명령의 코드페이지와 출력 디코더를 함께 맞추며, 멀티바이트 문자가 출력 조각 경계에서 깨지지 않도록 스트림으로 처리합니다.

설정을 변경한 뒤 VS Code의 `개발자: 창 다시 로드`로 전용 브라우저 연결을 다시 만드세요.
Copilot 입력창에 직접 작성 중인 내용이 있으면 덮어쓰지 않고 작업을 중단합니다.
응답은 요청별 ID가 일치하는 구조화된 JSON만 받습니다. 응답 형식 오류나 시간 초과 시 파일을 적용하거나 요청을 자동 재전송하지 않습니다.
현재 요청 ID가 같은 여러 JSON은 중복을 제거하고 합칩니다. 서로 다른 파일의 수정안은 한 묶음으로, 같은 파일의 부분 수정은 같은 hash일 때 함께 검증합니다. 동일 파일의 다른 전체 본문·다른 hash·상충하는 교체 내용은 응답 생성이 끝난 뒤에도 충돌이 유지되면 적용하지 않습니다. 겹치는 부분 수정은 로컬 파일 검증에서 거부합니다. 여러 완료 설명은 합쳐 표시합니다. 도구 요청과 수정안이 함께 오면 도구만 먼저 실행하고 실제 결과·hash로 수정안을 다시 받습니다. 미리 온 수정안이나 완료 설명을 실행 결과로 취급하지 않습니다.
응답 코드 블록은 표준 `json`을 사용합니다. 과거 `m365-agent` 언어 이름으로 인한 구문 강조 경고를 피합니다.
입력은 DOM의 문단과 실제 텍스트로 검증하고, 진단에는 요청·확인 글자 수와 표시된 한도를 포함합니다. 길이가 달라도 곧바로 길이 제한으로 단정하지 않습니다.
0.2.0이 남긴 식별 가능한 자동화 요청 초안은 다음 작업 전에 정리합니다. 일반 사용자 초안은 자동 삭제하지 않습니다. 자동 전송이 중단됐을 때 브라우저의 전송 버튼을 직접 누르지 말고 오류를 확인하세요.

## 동작 방식과 제약

`VS Code 파일 도구 ↔ Playwright ↔ 전용 Edge의 M365 Copilot 웹`

파일 내용은 사용자가 로그인한 M365 Copilot 웹에 프롬프트로 전달됩니다. 별도 개발자 서버, 텔레메트리, 다른 AI 서비스로 보내지 않습니다.
비공개 API 호출, 로그인 토큰 추출, 회사 보안 정책 우회는 하지 않습니다.
이 방식은 Microsoft의 공식 Copilot API 연동이 아니며 웹 UI 변경, 조직의 브라우저 자동화 정책, 사용량 제한에 영향을 받습니다.
Microsoft의 데이터 보호 설명은 적용 계약·관리 설정에 따른 보호를 설명하지만, 이 비공식 확장이나 브라우저 자동화의 사용 승인을 보장하지 않습니다. 회사의 DLP·코드 반출·브라우저 자동화 정책 및 적용 계약에 맞는 환경에서만 사용하세요. 로컬 파일을 웹 프롬프트에 붙이는 동작에 원본 파일의 민감도 레이블이 자동으로 따라간다고 보장하지 않습니다. [Microsoft의 기업 데이터 보호 설명](https://learn.microsoft.com/en-us/copilot/plan/enterprise-data-protection)을 참고하세요.
전용 Edge를 사용하는 웹 자동화입니다. 기본값에서는 화면을 VS Code 탭에 표시하며, 외부 모드의 브라우저 창을 직접 닫으면 다시 연결해야 합니다. 실제 회사 로그인과 응답 언어 동작은 해당 테넌트에서 검증해야 합니다.
WSL/SSH/컨테이너 등 원격 프로젝트는 이번 버전의 대상이 아닙니다.

## 브라우저가 열리지 않을 때

연결 실패 시 출력 패널의 **M365 Code Agent**에 실패 단계와 원인 코드를 자동으로 기록합니다. `⋯ → 연결 진단` 또는 명령 팔레트의 `M365 Agent: 연결 진단`은 브라우저가 실행되지 않아도 동작합니다. 확장·VS Code·Node/OS 버전, 선택한 브라우저·표시 방식, 기본 설치 위치 확인, 전용 프로필의 임시 쓰기 검사 결과와 최근 실패를 표시하며 브라우저를 다시 실행하지 않습니다. 기본 경로에서 실행 파일을 찾지 못한 결과만으로 사용자 지정 설치가 없다고 단정하지는 않습니다.

- `PROFILE_ACCESS_FAILED`: VS Code 확장 저장소 접근·쓰기 권한 또는 저장 공간을 확인합니다.
- `BROWSER_NOT_FOUND`: 선택한 Edge/Chrome 설치를 확인합니다. `PROFILE_IN_USE`이면 같은 전용 프로필을 사용하는 다른 VS Code 창의 M365 연결을 종료한 뒤 다시 연결합니다.
- `BROWSER_PANEL_FAILED`: VS Code 창을 다시 로드하거나 `m365Agent.browserView=external`로 화면 표시를 확인합니다.
- `BROWSER_CERTIFICATE_FAILED` / `BROWSER_PROXY_FAILED`: 회사 인증서·프록시·VPN 및 일반 브라우저의 M365 접속 상태를 확인합니다.
- `BROWSER_NAVIGATION_TIMEOUT` / `BROWSER_NAVIGATION_FAILED`: 브라우저 실행 이후의 페이지 로딩 실패입니다. 현재 창의 상태를 확인하고 다시 연결합니다.

페이지 로딩 실패 뒤에는 실행 중인 전용 브라우저를 재사용해 다시 연결합니다. 남아 있는 로그인 탭·정상 입력창은 보존하며, 오류 복구를 위해 프로필·쿠키를 삭제하거나 인증서/회사 정책 검사를 우회하지 않습니다. 출력에서 단계·원인 코드·실행 환경 결과를 확인할 수 있지만 이 진단만으로 실제 회사 환경의 원인이 해결됐다고 보장하지는 않습니다.

## 개발과 검증

### 실계정 확인 범위

2026-11-16에 0.13.2를 설치한 별도 VS Code 프로필과 업무 코드가 없는 예제 프로젝트에서 사용자 직접 로그인, 실제 Copilot의 프로젝트 분석 응답, 두 파일의 수정안 검토·적용을 확인했습니다. 테스트 명령은 모델에 JSON 프로토콜 도구라는 추가 안내를 한 뒤 승인·실행하여 `npm test`의 2개 통과·0개 실패를 확인했습니다. 모든 단계가 첫 요청만으로 완료된 것은 아닙니다.

0.13.3은 Agent의 도구 목록·호스트 실행 설명·명령 호출 예시를 보완합니다. 변경한 프롬프트를 실계정에서 다시 검증한 결과나 조직별 SSO·MFA·DLP·프록시 호환성 검증은 포함하지 않습니다. 자동 테스트의 모의 Copilot 응답과 실제 VS Code 호스트 검증은 실계정 확인과 구분합니다.

`npm test`는 브라우저 테스트 파일이 한꺼번에 Edge를 과도하게 실행하지 않도록 파일 단위 동시 실행을 2개로 제한합니다. 로그인 복귀 테스트는 고정 시간 대기 대신 로그인 대기 상태를 확인한 뒤 채팅 탭을 열며, 최초 요청이 한 번만 전송되고 인증 입력이 보존되는지 검사합니다.

```powershell
npm ci
npm run check
npm test
npm run test:integration
npm run package
```

`npm run check`는 ESLint, Prettier 포맷 검사, JSDoc 기반 타입 검사를 실행합니다. `npm run format`으로 런타임 JS·개발 스크립트를 정리할 수 있습니다. `tool-call.js`, `workspace.js`, `changes.js`, `agent.js`에 `// @ts-check`를 적용하고 `strict: true`, `noImplicitAny: true`로 검사합니다. create/edit/delete 제안, 원본 바이트가 필수인 복원 백업, 승인 호스트와 에이전트 전송 계약은 `types/contracts.d.ts`로 구분하며 VS Code API는 최소 지원 버전의 공식 타입을 사용합니다. 전체 UI 모듈까지 검사한 상태는 아닙니다. 실행 코드는 CommonJS JavaScript 그대로이며 TypeScript·Prettier는 개발 의존성입니다.

정리 테스트는 OS 임시 폴더에 독립된 저장소를 만들고 실제 경로로 정규화하므로 저장소의 `.test-output`이 없어도 단독 실행할 수 있습니다. Windows 드라이브 문자가 다른 대소문자로 전달되는 경우와, 삭제 계획 후 실행 상태가 바뀌는 경우도 검사합니다.

테스트 산출물 정리 명령은 기본적으로 삭제 예정 목록만 표시합니다.

```powershell
npm run clean:test-output
npm run clean:test-output -- --apply --keep=3 --older-than-hours=24
```

정리 범위는 이 저장소의 `.test-output/integration-*` 중 완료가 확인된 이전 실행 폴더뿐입니다. 최근 3개와 24시간 이내 결과를 보존하며, 실행 중인 프로세스·링크/정션·출처를 확인할 수 없는 폴더는 건너뜁니다. 새 실행에는 상태 마커를 기록하고 이전 성공 실행은 결과 보고서로 확인합니다. 프로젝트 코드·배포 파일·전용 Copilot 로그인 프로필과 상위 `.playwright-mcp` 기록은 이 명령의 정리 범위에 포함하지 않습니다. `--apply`를 지정해야 실제 삭제합니다. 계획 단계에서 후보 트리를 한 번씩 검사하고, 삭제 직전에는 보존 정책·현재 실행 목록을 갱신한 뒤 해당 대상의 트리와 완료 상태만 다시 확인합니다. 다른 후보 트리는 반복 순회하지 않습니다. 폴더 식별 정보가 바뀌거나 다시 실행 중이 된 대상은 삭제하지 않으며, 결과에 삭제한 파일 크기 합계(`removedBytes`)를 표시합니다.

무제한 루프 정책 단위 테스트는 메모리 데이터로 100회를 넘는 요청을 검증합니다. 실제 파일 읽기·해시·삭제·복원과 브라우저 UI 검증은 별도 실제 I/O 테스트를 유지합니다.

테스트는 로컬 파일 시스템, 해시·경로 보호, 모의 Copilot 페이지를 사용한 실제 Edge 입출력,
웹뷰의 키보드·한글 입력·승인 UI, 별도 VS Code 테스트 호스트의 파일 생성·편집·삭제·저장·원본 바이트 복원 및 명령 승인을 확인합니다. 모의 페이지 검증이 회사 테넌트의 연동 검증을 대신하지는 않습니다.
CI에서도 VS Code 확장 호스트를 실행해 큰 파일의 부분 수정과 실행 설정의 강제 검토를 검사합니다. 로컬에서 설치된 VS Code로 검증하려면 `M365_AGENT_VSCODE_PATH`에 실행 파일 경로를 지정할 수 있습니다.
배포 스크립트는 `.test-output`, Edge 프로필·쿠키·키 경로가 VSIX에 포함되거나 테스트 프로필이 Git에서 추적되면 패키징을 중단합니다. 소스 ZIP은 `git archive`로 생성하며 작업 폴더 전체를 압축하지 않습니다.
